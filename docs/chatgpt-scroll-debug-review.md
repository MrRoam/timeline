# ChatGPT 定位与滚动调试记录

版本：4.6.19。日期：2026-10-17。

本次同时使用实际加载扩展的 Chrome 和本地 Chromium 回归页。结论覆盖当前 manifest 启用的 ChatGPT 时间线、Pin、位置恢复与初始化链路。

## 已确认的问题与修复

| 问题 | 证据 | 修复 |
| --- | --- | --- |
| 跳转中目标被虚拟列表替换，动画直接退出 | 浏览器用例中目标距预期位置偏差超过 3000px | 保存消息身份；旧节点断开后重新查找 |
| 历史回答在动画结束后展开，目标再次偏移 | 前方回答增加 300px 后，定位也偏移 300px | 动画结束后保留 1600ms 修正窗口；主动操作立即取消 |
| Pin 与刷新恢复只记像素位置 | 前方历史增加 200px，返回点也错位 200px | 同时保存消息身份和消息内偏移；发送前快照与候选 Pin 保留同一锚点 |
| 扩展向宿主消息列表插入占位节点 | 24 个宿主子节点变成 25 个；零高度节点仍会增加 flex gap | 删除占位机制，不再改动宿主列表的子节点和高度；短回答在真实底部激活最后提问 |
| 多个滚动动画互相竞争，销毁后回调仍可能运行 | 原实现未保存动画帧句柄，也没有取消入口 | 新导航、滚轮、触摸、阅读区域点击、滚动键、发送和销毁均取消旧导航 |
| 初始化重试销毁已经建好的实例 | 同一版本的就绪回调与延迟重试造成两次初始化 | 初始化入口复用已就绪实例，拒绝过期版本 |
| 异步读取旧位置覆盖用户的新导航 | 存储读取完成前主动跳转，旧位置仍会写回 | 恢复前核对导航版本、会话地址、用户操作和销毁状态 |
| 文档自身滚动时坐标重复计入 scrollTop | document 回归模式验证真实视口几何 | 文档滚动以视口顶部为零；普通容器计入边框 |
| 当前 ChatGPT 原生消息与匿名路由无法识别 | 实页使用 `data-message-role`、原生 `id` 和 `/uc/`；没有旧属性或 `h4.sr-only` | 优先使用现有稳定消息属性，保留旧结构兼容 |

以上修复没有新增权限、注入脚本或运行时依赖。

## 真实 ChatGPT 页面验收

使用独立 Chrome 测试会话，在 `https://chatgpt.com/` 发送三轮测试问题，分别生成多行列表。验证结果：

- 时间线节点随提问从 1 增加至 3。
- 点击首个节点后，首个提问停在滚动视口顶部下方 20px。
- 阅读首个回答并设置 Pin，追加第三轮回答后返回，原回答位置误差为 0px。
- 三个回答均完成；首个回答的文本长度在追加输出前后保持一致。
- 宿主页面没有 `.ait-scroll-padding`，浏览器没有报告脚本异常。

该会话未登录。用户账号内的长对话尚未验收。“已有回答无法加载”没有在这组三轮实页测试中复现；已移除确定会干扰宿主几何的占位节点，但不能据此认定该症状的唯一原因已经确认。

## 自动回归

验证结果：73 项 Node 测试、45 项真实浏览器检查全部通过；JavaScript 语法与补丁空白检查通过。Chrome 打包成功，解压目录的运行代码与源码一致。

```text
node --test tests/*.test.js
node scripts/test-browser.js
node --check js/timeline/index.js
node --check js/timeline/adapters/chatgpt.js
node --check js/timeline/timeline-manager.js
git diff --check
```

浏览器回归需要外部安装的 `agent-browser` 和 Chrome/Chromium，不需要项目构建或 `package.json`。`AGENT_BROWSER_BIN` 可指定 CLI 可执行文件，`TIMELINE_TEST_CHROME` 可指定浏览器。回归页按照 manifest 顺序加载实际脚本与样式，仅模拟扩展存储接口和平台检测；布局、滚动、动画帧与观察器均由真实浏览器执行。

浏览器用例覆盖旧消息 DOM、角色标题 DOM、虚拟轮次空壳、原生消息属性与文档滚动五种结构。每种结构检查节点替换、延迟展开、Pin、流式追加、连续点击、主动滚动取消、短回答的底部定位、销毁清理及宿主节点完整性。

边界：修正窗口有期限；超过期限才发生的宿主布局变化仍可能需要再次定位。宿主完全卸载消息且不保留稳定空壳时，不伪造坐标。没有稳定 ID 的旧标题结构仍使用现有索引回退。
